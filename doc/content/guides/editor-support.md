`thp-lsp` 0.1.0 is released independently from the THP compiler under
`thp-lsp-v*` tags. Configure an editor's generic LSP client with language ID
`thp`, file extension `.thp`, and either `thp-lsp` or `thp-lsp --stdio`. Both
forms communicate exclusively through Language Server Protocol messages on
standard input and output; diagnostics and logs never use standard output.

`thp-lsp --help` and `thp-lsp --version` are terminal commands; starting the
binary without arguments begins the protocol stream and is intended for an
editor rather than an interactive terminal.

The server publishes diagnostics and supports hover, completion, signature
help, definition, references, safe prepare-rename and rename, document and
workspace symbols, full semantic tokens, and full-document formatting. Rename
uses document versions for open files, preserves `$` on variables, groups
overridden and implemented methods, and declines unresolved, ambiguous,
dynamic, built-in, and namespace targets. Formatting preserves comments,
literals, line breaks, blank-line count, line-ending style, and final-newline
presence; invalid syntax produces no edits.

Editor plugins and syntax grammars are released from separate repositories.
Version 0.1.0 does not advertise code actions, inlay hints, call hierarchy,
range formatting, incremental synchronization, or TCP transport.

## Workspace discovery

Each workspace folder is an independent THP project boundary. A `thp.toml` is
loaded only when it exists at that exact folder root. Its `[autoload]`
directories are validated before source discovery; missing, unreadable,
ambiguous, and overlapping mappings are reported against the configuration.
Mapped `.thp` files are declaration-only modules whose namespace and relative
path must match the configured prefix. Other `.thp` files below the workspace
are independent entrypoints analyzed against the shared modules. Without a
`thp.toml`, every workspace `.thp` file is analyzed independently.

Directory symlinks are not followed. Unsaved editor text overlays the matching
canonical path, and opening, closing, creating, changing, or removing a file
rescans the affected workspace. Files outside all workspace folders remain
standalone documents.

## Documentation comments

Place a documentation block immediately before a function, class, interface,
trait, method, or property:

```thp
<?thp

/**
 * Looks up one user.
 *
 * @param int $id Persistent user identifier.
 * @return ?User The user, or null when it does not exist.
 * @throws LookupException When storage is unavailable.
 */
function findUser(int $id): ?User {
    // ...
}
```

Supported tags are `@param`, `@return`, `@throws`, `@var`, `@deprecated`,
`@internal`, `@since`, and `@see`. Types use THP syntax and namespace/import
resolution; PHPDoc-only pseudo-types are not accepted. Unknown tags are retained
without diagnostics but are not rendered.

## Local `@var` hints

A PHP-style local hint must immediately precede an assignment to the same name:

```thp
<?thp

/** @var User $user */
$user = loadUser();
```

The hint applies from that assignment to the end of its function, method, or
top-level program. A later valid hint for the same local replaces it. It can
guide variable hover, member completion, and method signature lookup even when
the compiler inferred another type. The inferred compiler type remains visible
as secondary hover context.

This is deliberately non-semantic: `@var` does not suppress compiler errors or
change call resolution, generated bytecode, or runtime behavior.
